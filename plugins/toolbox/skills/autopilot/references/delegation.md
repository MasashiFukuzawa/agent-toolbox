# 任せる範囲の雛形

案件の指示ファイル（`AGENTS.md` など）に、次の節を置く。短く保ち、対象・操作・条件が分かるように書く。「必ず聞くこと」が、いちばん効く。

```markdown
## 任せる範囲

### 聞かずにやってよいこと
- このリポジトリのコードとテストの編集、検査の実行、ブランチとPRの作成。
- 実装の手段、形式の選択、仕様の細部の解釈のうち、戻せるもの。決めたことはゴールのページに残す。
- このゴールのために作ったworktree・ブランチ・コンテナ・一時ファイルの片付け（未commitの変更、未pushのcommit、データが残るものを除く）。
- <この案件で許すもの。例: 検証用の環境への反映>

### 必ず聞くこと
- データの削除、戻せない操作。
- 外部への送信・公開。
- 費用のかかる操作（<上限>を超えるもの）。
- 本番への反映、権限や公開範囲の変更。
- 人しか知らない事実。
- <この案件で必ず聞くもの>

### 検査とマージ
- 検査: `<コマンド>`
- マージ: <人が承認する ／ ローカルの動作確認・CI・第三者の確認が通れば自動>
```

## 置き場

| 置き場 | 入れるもの | 読まれ方 |
|---|---|---|
| 案件の指示ファイル | チームで共有してよい決まり | ホストが自動で読む。worktreeは、最新の既定ブランチから作る |
| `.agents/autopilot.json` | マージと本番への反映が自動か人の承認か、タスクの取り方 | `autopilot_board.py preflight` で読む |
| `<git-common-dir>/info/delegation.md` | 自分だけの決まり | autopilotが開始時に読む。そのPCの、同じリポジトリのworktreeで共有される |

- 個人の決まりで、チームの決まりを緩めない。食い違う時は、チームの決まりに従い、人に伝える。
- 合意した時に読んだ版（commit）を、ゴールのページの「合意」に書く。マージや本番への反映の前に、決まりが変わっていないかを見る。権限を取り下げる変更は、すぐ従う。

## 決まりを足す・直す

- 人が明言した決まりは、言われた範囲のまま1行足す。例: 「本番への反映は、時間帯の承認を待たなくてよい」は、誰が反映するかの決まりを変えない。
- 1回の「はい」を、別の対象や環境へ広げない。広げたい時は、広げた文を示して確認する。
- 古い決まりと食い違う時は、古い方を直す。期限のある許可には、期限を書く。
- sandboxがGitディレクトリや `.agents/` への書込みを止めている時は、足す1行を示して、人に追記を頼む。
