# セッション間の運用

## 正本と更新担当

統合役と各担当の識別子、板の場所、更新担当、連絡手段を開始時に共有する。
統合役を特定できない場合は、最初に受けたセッションを勝手に全体の承認者にせず、担当の確認を一度行う。
同じ板の更新担当は一つのセッション。引継ぎは旧担当の停止・引継ぎを確認し、板のmaintainerと参照先を更新する。
同じオーナー名や同じdirectoryだけで更新権限を推測しない。

| 内容 | 正本 |
|---|---|
| 判断・承認・権限・優先度・セッションをまたぐ事項 | 統合役の板 |
| 担当内で完結する設計の選択・事実確認 | 必要なら担当板。統合板からリンク |
| 詳しい背景・図解 | 別HTML。関連するQ番号と連絡板への戻り先を明記 |
| 計画・タスク・実装・実環境の証拠 | 元の正本。連絡板に第二の台帳を作らない |

担当板の問いが横断事項になったら、統合役へ渡す。
元のIDを使った参照を残し、独立した質問として二重に回答待ちにしない。
統合板では担当板へのリンクだけを置くか、新しい統合Qへ引き継いだことを元の記録に明記する。

## 回答を受け取ったら

1. 対象の作業・板・Q番号を確認し、番号だけで別の作業の回答と取り違えない。
2. 回答の原文、受領時刻、許可された範囲を更新担当へ伝える。回答に秘密が含まれていたら、それを再送・記録しない。
3. 統合役と関係担当へ、依存する操作に進む前にすぐ中継する。複数の関係担当を一つの「共有済み」で丸めない。
4. 中継先ごとにpending/sentを保持し、送信成功を確認してからsentにする。
5. 更新担当が回答と中継状態をJSONへ反映し、再生成する。受領したセッションが他の板を無断で直接編集しない。

中継に使う短い文の例:

```text
対象：作業識別子 / 統合板 Q12
回答：1。少人数で先に確認する
受領：タイムゾーン付きの実時刻
影響：確認対象の選定。公開範囲の変更や追加費用の許可は含まない
次の対応：担当が準備し、統合役へ結果を返す
正本：連絡板のリンク
```

利用可能で許可されたホストのセッション間通信を使う。
通信手段がなく更新担当へ伝えられない場合、受領セッションのrepo外の永続引継ぎ文書へ、
板・Q番号・秘密を除いた回答原文・受領時刻・中継先・未送信状態を保存する。context-handoffがあれば利用する。
受領側は板を編集せず、更新担当の受領前に板へpendingを反映できたと報告しない。
この場合に限り、チャットへ「更新担当に貼る短い中継文」と引継ぎ文書へのリンクを返し、中継をオーナーへ依頼する。
理由は更新担当へ通信できないことであると伝える。書込先もない場合は永続記録不能を明示する。
更新担当が受領したら板へ回答と未送信先を反映する。自動中継やQ番号だけでのスキル発火は保証しない。
メールや外部Chatへ送る権限を、連絡板運用の依頼から推測しない。

## 回答は実行権限そのものではない

選択肢に示した対象・操作・環境・条件へ回答を結び付ける。新しい操作や費用へ広げない。
回答待ちは依存する操作だけを止め、既存権限内の独立作業は続ける。
「解説して」、表示形式への感想、準備中の問いへの反応を、merge/deploy等の承認に読み替えない。

回答の訂正・衝突があれば、対象Qのanswer.textへ受領時刻付きの訂正原文を追記し、原回答を上書きしない。
訂正で未完了になったfollow_upと、訂正を再共有する中継先をpendingへ戻す。
対応待ちをsummaryに明記し、影響する操作だけを止める。確認が必要なら新しいQで問い、元Qとの関係を背景に記す。
解釈で結果が変わる場合にだけ確認し、compactionやセッション交代だけを理由に回答を取り直さない。
