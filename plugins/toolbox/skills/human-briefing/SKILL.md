# Human Briefing — 人に伝える型

読み手が聞き返さずに「何の話か・何が困るのか・どうなれば終わりか・自分は何をすればよいか」を答えられる状態にする。人への依頼・相談・報告の型はここだけで定め、媒体ごとのスキルは置き場所と見た目を定める。

## 4行

この順に、この行名で書く。1行は1〜2文、80字程度まで。

| 行 | 読み手の問い | 書くこと |
|---|---|---|
| 背景 | 何の話で、どこの話か | 対象（利用者から見た機能・画面・工程）と、読み手が知らない前提・用語 |
| 課題 | 放っておくと何が困るか | きっかけになった事実と、誰に・何が・どれだけ起きるか。数字と期日で書く |
| 目的 | 何が満たされれば終わりか | 到達したかを確かめられる状態 |
| 相談事項 | 自分は何をすればよいか | 決めてほしいことと推奨、または頼みたい作業（次節） |

- 頼むことが無い報告では、4行目の行名を「実施事項」に替える。最初に「依頼なし」と書き、済ませたことと次に行うことを続ける。
- 1つの事実は1つの行にだけ書く。対象と前提は背景、困りごとは課題に置く。経緯は書かない。
- 書き終えたら行ごとに読み手の問いを当て、その行だけで答えられるまで書き直す。

| 行 | 聞き返される書き方 | 答えられる書き方 |
|---|---|---|
| 背景 | 通知の再送が未決 | 予約確認メールは、予約の直後に利用者へ届く通知。送信に失敗した分は、今は再送されない |
| 課題 | 早めに決めたい | 先週は送信の失敗が1日平均40件あり、予約できたか分からない利用者からの問い合わせが1日12件来ている |
| 目的 | 通知を安定させる | 失敗から10分以内に再送され、この問い合わせが週10件未満になる |
| 相談事項 | 再送方法を決める | 再送を自動にするか決めてほしい。推奨は自動再送（3回まで）。決め手は人手の作業が無くなること |

## 相談事項の中身

### 判断を頼む

- 1つの依頼で決めてもらうことは1つ。切り離せない場合でも2つまでにし、それを超える分は別の依頼（連絡板なら小問）に分ける。
- 選択肢の番号か「はい／いいえ」で答えられる問いにし、返信例を添える。
- 推奨を1つに決める。決め手は、推奨案だけが持ち他案に無い理由を1つ選ぶ。選択肢ごとの良い点と欠点は比較に回す。
- 期限は日付・時刻・タイムゾーンで書き、決めない場合に起きることを添える。
- 回答によって次の動きが変わるなら、回答後に起きることを書く。
- 図を1つ添える。前後の比較か、選択肢の比較を選ぶ。選択肢より前に置き、折りたたまない。チャットではascii-diagramの小図か短い比較表、HTMLではhtml-artifactの「図で語る」に従う。

### 作業を頼む

番号付きの手順、入力値、所要時間、返してほしいこと、やらない場合に起きること、返信例を書く。

## 先回りの確認

読み手が返信の前に聞き返す定番の4つ。当てはまるものを、相談事項のすぐ後に1行ずつ書く。

| 確認 | 書くこと |
|---|---|
| 変更の大きさ | 何がどれだけ変わるか。画面・設定・対象の利用者・手順の数など、読み手に見える単位で書く |
| 日々の使い勝手 | 利用者や開発者の毎日の操作・待ち時間・手順が増えるか減るか。変わらなければ「変わらない」と書く |
| 戻せるか | 戻せるかどうかと、戻す方法、戻すのにかかる時間 |
| 待ち時間の根拠 | 待つ期間や制限を置く理由と、短くできる条件。理由を書ける待ちだけを計画に入れる |

## 書き方

- 読み手に見える効果を先に書く。「何をしたか」より「何ができるようになるか」。
- Issue・PRの番号、作業中に付けた呼び名、略号は、内容を言葉で書いた後の括弧に入れる（例「取り込みの再試行（#412）」）。
- 表のセルは1行にする。文になるなら、表をやめて箇条書きか図にする。
- 見出しと図の数字は、本文を数え直して一致させる（「6つとも」と書く前に数える）。
- 数字・期日・条件は入力にあるものを使う。推定は「推定」、確かめられないものは「未確認」と書く。
- 文末には、何をどう変えるかを書く。「整理する」「対応する」「検討する」で終えた文は書き直す。

## チャットで使う

人に判断や作業を頼むメッセージと、作業結果の報告は、チャットでも行名を付けた4行で書く。

```text
背景：予約確認メール（予約の直後に利用者へ届く通知）の再送の話です。
課題：送信の失敗が1日平均40件あり、問い合わせが1日12件来ています。
目的：失敗から10分以内に再送され、この問い合わせが週10件未満になること。
相談事項：再送を自動にしてよいですか。推奨は「はい」（3回まで自動再送）。決め手は人手の作業が無くなること。
戻せるか：設定1か所で止められます（数分）。
返信例：「はい」
```

- 直前のやり取りで背景と課題を共有済みなら、相談事項（または実施事項）だけでよい。話題が変わった、時間が空いた、読み手が別の作業から戻る、のどれかに当たれば4行に戻す。
- 依頼が複数あれば、依頼ごとに番号を振り、それぞれを4行で書く。
- 手順や入力値が長い依頼は、連絡板か資料に置き、チャットには相談事項とリンクを書く。

## 媒体ごとの役割

| スキル | 担当 |
|---|---|
| human-briefing | 4行、相談事項の中身、先回りの確認、書き方 |
| html-artifact | 一枚物HTMLの構成（結論ブロックに4行を置く）、見た目、図の描き方、保存先 |
| owner-board | 継続する依頼の連絡板。画面構成、Q番号、回答の記録、中継 |
| daily-plan | 最大24時間の計画ページ。依頼の中身は載せず、Q番号で連絡板へつなぐ |
| progress-report | 報告に載せる事実の選び方（目的・現在地・残る条件・次の判断） |
| context-handoff | 次の作業者向けの再開文書。冒頭の要約を4行で書く |
| ascii-diagram | チャット内の図 |

## 出す前の確認

1. 初見の人が、4つの問いに各行だけで答えられるか。
2. 1つの依頼で頼む判断は1つ（多くて2つ）か。返信例のとおりに答えられるか。
3. 判断の依頼に図があり、選択肢より前に、開かなくても見えるか。
4. 当てはまる先回りの確認を書いたか。理由を書けない待ちが残っていないか。
5. 番号や呼び名が主語になっていないか。見出しの数字は本文と一致するか。
