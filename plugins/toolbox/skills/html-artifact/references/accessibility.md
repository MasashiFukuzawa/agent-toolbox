# アクセシビリティと検証

基準の参照先は [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/) と [Understanding](https://www.w3.org/WAI/WCAG22/Understanding/)。以下は資料で頻出する確認点であり、全達成基準の網羅監査ではない。

## 情報を見失わない

- 通常文字は背景と4.5:1以上、大きい文字は3:1以上を目安でなくAAの基準として確認する（1.4.3）。図の意味を担う部分やUIの識別に必要な表示も背景との区別を確認する（1.4.11）。装飾線まで同じ基準と混同しない。
- 色の違いだけで成功/失敗、担当、系列を表さない。ラベルや形を併用する（1.4.1）。
- 図に短い要点説明を添え、詳細な数値や関係が判断に必要なら表/文章でも辿れるようにする（1.1.1）。SVGはtitle/descとaria-labelledby等で名前を付け、装飾ならaria-hiddenにする。図全体の名前だけで内容の代替になるとは限らない。
- 表はcaption/見出し、thとscopeで対応を示す。見た目のためにtableを使わない。見出し順とDOMの読み順で意味が伝わるようにする（1.3.1、1.3.2）。

## 操作と表示

- Tab/Shift+Tabで全操作へ到達し、Enter/Spaceなどnative要素の操作が使えるか確認する。focusの見失い・trap・覆い隠しを避ける（2.1.1、2.1.2、2.4.7、2.4.11）。
- buttonは操作、aは移動、details/summaryは折りたたみ。クリック可能なdivや隠したradioで独自tabを作るよりnative要素を優先する。
- 重要な説明は常時見える短文か操作可能なdetailsにする。hover/focus popupを使う場合は閉じられ、pointerで移動でき、必要な間表示が続くことを確認する（1.4.13）。単純な資料ではtooltip自体を省く方がよい。
- 200%の文字拡大と、狭い表示へのreflowを確認する（1.4.4、1.4.10）。通常本文は横スクロールを要求しない。二次元の関係が必要な表/図はその領域だけスクロール可能にし、内容を欠落させない。
- 動きを省略しても意味が成立するようにし、prefers-reduced-motionを尊重する。自動再生や点滅は原則不要。

## 検証の深さ

実表示で重なり・文字切れ・コントラスト・keyboard・拡大を確認する。ブラウザのaccessibility treeや自動検査が利用できれば補助に使うが、自動検査だけで準拠を宣言しない。読み上げ未検証などの限界はそのまま報告する。

印刷/PDF化が要件なら印刷時も結論と根拠を失わないか確認する。detailsを自動で開く場合は印刷後に元の状態へ戻し、巨大な図の切断を確認する。印刷が不要なら専用の複雑な制御は足さない。
