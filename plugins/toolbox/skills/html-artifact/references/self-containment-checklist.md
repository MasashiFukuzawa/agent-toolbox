# Self-containment and delivery checks

The default is one HTML file whose essential content remains readable offline, with inline CSS/JS, inline SVG and system fonts. External dependencies require an explicit need, a visible limitation and an offline fallback for essential content.

- Include doctype, correct document language, UTF-8, viewport and a descriptive title.
- Do not fetch a backend, embed external sites or include credentials.
- Keep images embedded or omit them. External evidence links are references, not rendering dependencies.
- Use semantic headings, table headers and native controls. Check the accessibility reference.
- Keep conclusion, decisions and material risks visible. Details are optional supporting evidence, not a mandatory component quota.
- Explain unfamiliar terms inline when possible. A glossary is optional; links must resolve if used.
- Confirm content/visual agreement, units, uncertainty, links, keyboard operation and enlarged/narrow layout.
- Report whether the page was actually rendered. Launching an open command is not proof of visual inspection.
- If printing is requested, inspect print output, including any closed details. Do not add print scripts when unnecessary.
- Use browser tools in an isolated artifact directory. Never delete files merely because they appeared after a browser call; confirm ownership first.

No palette, theme, file-size or glossary-count requirement applies. Clarity and accessibility are the acceptance criteria. Follow SKILL.md for delivery paths and the concise user-facing report.
