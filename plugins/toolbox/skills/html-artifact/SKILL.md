# HTML Artifact — 判断できる一枚物

読み手が初見でも結論・関係・選択肢を掴めるHTMLを作る。文章は必要最小限、図表は積極的に使う。固定テンプレート、配色、図の数を満たすことではなく、理解と判断を助けることを優先する。

## 先に決めること

誰が読み、何を理解/判断する資料かを文脈から一行で定める。複数の問いがあってよいが主目的を明確にする。合理的に分かれば確認で止めず、判断が変わる不明点だけ尋ねる。HTML冒頭のコメントへ主目的を残す。

進捗報告の内容選択はprogress-report、表現は本スキルが担う。ユーザーが指定した焦点・読み手・様式を尊重し、HTML化のついでに対象を広げない。

`progress-report --html` からの連携では、整理済みの根拠・基準時点・状態・判断材料を使い、内容選択のためにprogress-reportを呼び戻さない。`--ascii` も指定されている場合、会話内要約との事実・結論を揃えつつ、HTMLには媒体に適した図表を選ぶ。章立てや図種は固定しない。

## 情報設計

- 冒頭で結論/推奨、現在地、重要な判断が分かるようにする。主図や比較表が結論を伝えるなら、それを中心に置く。
- 重要なリスク、判断期限、推奨を覆す条件を折りたたみに隠さない。背景は理解に必要な分だけ近くに置く。
- 不要な情報は削る。必要な補足だけdetailsや根拠リンクに分ける。「全部残して折りたためば簡潔」と考えない。
- 数字には単位・時点・母数・根拠を付け、事実/推定/不明を区別する。正確さを第一にし、見栄えのために進捗率や日程を創作しない。
- 同じ主張をKPI帯・カード・要約・表で繰り返さない。行数/字数の達成ではなく読む負担を減らす。

## 図表の選択

図表は多めを既定とするが、短文より理解が改善する場合に使う。図種の数をノルマにしない。複数の異なる関係をすべて箱と線へ押し込まない。

| 伝える関係 | 第一候補 | 注意 |
|---|---|---|
| 選択肢の比較 | 比較表、並列配置 | 同じ軸で比べ、推奨理由を添える |
| 時間・順序・待ち | タイムライン、工程帯、担当別レーン | 期間未確定を確定の長さで描かない |
| 量・差・余裕 | 棒、ドット、幅を持つ区間 | 軸・単位・不確実性を明示 |
| 担当・状態の対応 | マトリクス、状態表 | 色だけに意味を持たせない |
| 構造・包含 | 入れ子、層、ツリー | 装飾の箱を増やさない |
| 本当の依存・流れ | ノードと線、分岐、シーケンス | 線の意味と方向を明確にする |
| 少数の事実・理由 | 短文、箇条書き、注釈 | 図が説明を難しくするなら描かない |

図のラベルを長文にして文章を移すだけにしない。各図が何を伝えるか短い見出し/キャプションで示す。画像化した表より意味のあるHTML表、静的な図ならinline SVG/CSSを優先する。

## 表現の自由度

レイアウト・配色・書体・図形は読み手と内容に合わせて選ぶ。assets/templatesと[visual-system](references/visual-system.md)は任意の出発点であり、固定ブランドや強制規則ではない。使わないサンプル、用語集、空セクションは除く。

テーマは常にライトのみを設計・実装・検証する。ダークテーマ、`prefers-color-scheme` による切替、テーマ切替UIは作らない。CSSに `color-scheme: light` を指定し、OSのテーマ設定にかかわらずライト表示を保つ。ライト前提でもコントラストは確保する。

用語は平易に言い換える。必要なら初出で一言説明する。用語chip・tooltip・用語集は必要時だけ。全用語を機械的にchip化せず、重要な意味をhoverだけへ隠さない。

既定は静的な資料。details、フィルター、コピー機能は読み手の具体的な負担を減らす場合だけ加える。操作説明やJavaScriptなしでも結論と主要な根拠を読めるようにする。対話的な編集アプリや連続スライダーは明示依頼がない限り作らない。

## アクセシビリティ（必須の品質）

制作・確認時に [アクセシビリティと検証](references/accessibility.md) を読む。

- 色だけに依存しないラベル、読みやすいコントラスト、十分な文字サイズを使う。
- 意味に合う見出し・table/th・button・a・details/summaryを使い、DOMの読み順と見た目を揃える。
- キーボードで操作でき、focusが見え、隠れたり閉じ込められたりしない。hover専用の重要情報を作らない。
- 図に代替となる要点説明、必要ならデータ表を添える。SVGの名前だけで複雑な関係の説明を済ませない。
- 拡大・狭い表示でも内容や操作を失わない。デスクトップ資料でも固定幅で文章を切らない。大きな表/図は必要部分だけ横スクロール可能にする。
- 動きは任意で、低減設定を尊重する。重要情報をアニメーションだけで伝えない。

チェックしただけでWCAG準拠を断言しない。実施した検証と未確認を区別する。

## 自己完結と安全

一つのHTML、inline CSS/必要最小限のJS、system font、inline SVGを既定にする。doctype、本文言語のlang、UTF-8、viewport、意味のあるtitleを持つ。資料データはそのまま埋め込む前に機密・個人情報と共有範囲を確認する。secretや認証情報は含めない。

外部CSS/JS、CDN、外部フォントは既定では使わない。明示要件で必要なら依存とoffline時の制限を記し、主要内容を読めるfallbackを用意する。backendへのfetchや外部iframeを資料へ追加しない。詳細は必要時に [self-containment checklist](references/self-containment-checklist.md) を参照する。

## 検証と納品

1. 数値、根拠、結論と図表の一致、参照リンク、サンプル残りを確認する。
2. 利用可能なブラウザで実際に表示し、文字の欠け、重なり、図の読みやすさ、拡大、keyboard操作を確認する。DOM測定だけで視覚的な分かりやすさを検証済みにしない。ブラウザ操作前にbrowser-operationsを読む。
3. 開けない環境なら未表示確認と明示する。ファイルをopenする命令が成功しただけで目視確認済みとは言わない。
4. 図や操作を編集したら影響する検証をやり直す。主観チェックの固定回数制限は置かず、同じ観点の無益な反復は避ける。

保存先はユーザー指定 → repoが明示するartifact慣習 → repo外のsession成果物領域。長期参照される報告は一時directoryより永続artifact領域を選び、正本とは混同しない。他者の作業ツリーへ副産物を混ぜない。自分が作成したと確認できないファイルをcleanupしない。

必要なら成果物専用directoryだけをlocalhostへ配信する。repo rootやhomeをHTTP公開しない。自分が起動したserverだけを停止する。

HTMLの作成・更新後は、保存した最終版をOSの標準の方法で開く。macOSは `open "<HTMLの絶対パス>"`、Linuxは `xdg-open "<HTMLの絶対パス>"`、Windows PowerShellは `Invoke-Item -LiteralPath '<HTMLの絶対パス>'` を使い、実際のパスはshellに合わせて安全に引用する。ユーザーが開かないよう指定した場合は従う。GUIや起動コマンドが利用できない場合、または起動に失敗した場合は、開けなかった理由を報告する。ブラウザでの検証とは別に、最終版をユーザーが見られるよう開く。

チャットには結論・主な図・絶対パスのリンクを短く返す。HTML全文、ファイルサイズ、行数、簡潔さの自賛は不要。
