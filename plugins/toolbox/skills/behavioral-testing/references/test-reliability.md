# 信頼でき、安く回るテストの書き方

新規・変更するテストが、時間の経過を待つ、プロセスを起動する、環境変数・ファイル・ポートに触れる、遅い・不安定である、またはテストファイルを新しく足す場合に読む。該当する場面の書き方の指針であり、全項目を埋めるチェックリストやゲートではない。プロジェクトやホストが「変更を反証できる最小の確認を走らせる」と定めているなら、そちらを優先する。

## 待たずに時間を制御する

- 固定の `sleep` を、テストが観察または解放できる合図に置き換える。長い timeout、retry、platform ごとの skip で `sleep` を隠さない。
- プロセスをまたいで実時間の経過が要る場合は、試行回数ではなく単調時計の期限（ミリ秒）まで poll する。例: 偽の CLI はテストが書く解放ファイルを待ち、テストは CLI の ready ファイルを期限まで poll する。
- 後で assert する状態は、すべて poll の条件に入れる。
- 子プロセスの次の段階は、タイマーではなく、テストが書くファイルや pipe で解放する。
- 非同期操作の後は、呼び出しが返るのを待つのではなく、その操作が作る状態を待つ。
- 同じプロセス内では、本番の既定値を持つ実際のオプションで時間を短縮・前進させる（例: `deadlineMs = DEFAULT_DEADLINE_MS`）。テスト専用の export・flag・global・hook は足さない。

## 実時間の速さを assert しない

- 操作回数を数えるか、退行すると極端に遅くなる入力を選び、結果だけを assert する。

## プロセスの起動を減らす

- 解析や入力検証は、プロセス内でテストする。
- 実プロセスを起動するテストは 1 ファイルあたり少数にし、終了コード・シグナル・標準入出力に絞る。
- 互いに独立した子プロセスは、順番にではなく同時に起動する。
- 実環境やネットワークでしか起きない不具合は、オフラインで安全に動く最小の構成で再現する。実環境でしかできない確認は、狭い範囲の任意実行にする。

## 隔離と復元

- `HOME`、`XDG_*`、`TMPDIR` をテストごとの一時 directory へ向け、開発者の実際の設定に触れないようにする。
- 環境変数・時計・モックを元に戻す。OS や外部との境界への故障注入は、元に戻すなら使ってよい。
- 一時 directory を消す前に、ファイルハンドルと子プロセスを閉じる。
- 固定のポートではなく、ポート 0 に bind する。
- 不安定なテストは共有状態を掃除して直す。直列実行にして隠さない。

## 失敗時の診断

- 子プロセスは、終了コードより先に stderr を assert するか、失敗メッセージに stderr を含める。

## 表形式のケース

- 既存の表（ケースのリストを回す形）に行を足す。行を足すのは、振る舞いが異なる場合だけにする。

## 不安定なテストの切り分け

- まず元の実行順で再現する。順序を変えた時だけ落ちるなら、共有状態の漏れを疑う。
- fixture の状態、完了の合図の欠落、製品側の競合を分けて考える。
- 状態を使う側ではなく、状態を作る側を直す。
- 再実行の回数は、再現した失敗の形から決める。固定回数の連続成功を要求しない。
- 何かを削除したことで落ちたなら、戻す前に、なぜ削除されたのかを読む。

## 実行経路に載っているか

- 新しいテストファイルが、実際の runner から見つかるようにする。discovery のパターン、wrapper、テストを選ぶ CI job を確認し、そのファイルが実際に実行されたことを確かめる。

## コスト

- 1 秒程度を超えるテストは、何に時間がかかっているかを言えるようにする。遅いテストは、より安い層では証明できないことを証明するものに限る。所要時間は報告に書く事実であり、手順ではない。
